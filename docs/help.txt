GUIDA OPERATIVA E MANUALE DEI COMANDI
========================================

  cdp <COMANDO> [OPZIONI]

========================================
FLUSSO OPERATIVO STANDARD (QUICK START)
========================================

Passo 1. Calibrazione Iniziale (Obbligatoria):
  $ cdp run RUN0

Passo 2. Esecuzione Batteria o Singolo Test:
  $ cdp run ALL_FOUNDATIONAL
  $ cdp run T01 --regime pilot --pacing 4
  $ cdp run T12 --mde 100.0

Passo 3. Consultazione Referto SOTU Master:
  $ cdp show latest

Passo 4. Compilazione Dossier di Campagna:
  $ cdp summary

========================================
1. GATEWAY CLI PRINCIPALE (cdp)
========================================

  cdp run <TEST_ID> [OPZIONI]
    Esegue una sessione di test formale.
    Target: RUN0, T01..T14, ALL_FOUNDATIONAL, ALL.
    Opzioni disponibili:
      --pacing <SEC>
        Intervallo di sicurezza in secondi tra chiamate API per rate limit (default: 4).
      --provider <NAME>
        Provider target (es. groq, gemini, mistral, openrouter). Se omesso, delega alla configurazione attiva di bash4llm.
      --model <MODEL_ID>
        Model ID esplicito per l'esecuzione. Se omesso, delega al default attivo di bash4llm.
      --regime <pilot|confirmatory|R1|R2>
        Regime sperimentale: pilot (N=5) | confirmatory (N=20). Default: pilot.
      --endpoint <URL>
        Endpoint URL per stima telemetrica baseline RTT.
      --mde <FLOAT>
        Minima Differenza Rilevante in ms per T12 (default: 100.0).
      --bash4llm-bin <PATH>
        Percorso esplicito dell'eseguibile SUT (bash4llm).
      --vault-ctx <PASS>
        Passcode master per sblocco in memoria del Vault OpenSSL.
      --dry-run
        Simulazione locale senza traffico HTTP di rete.
      --debug
        Preserva le sandbox temporanee per analisi forense.

  cdp summary [--out <FILE>]
    (Alias: dossier, synoptic)
    Scansiona runs/ e genera il Dossier di Campagna con Quadro Sinottico e curve di decadimento T14.
    Default: <WORKSPACE_DIR>/DOSSIER_CAMPAGNA.md

  cdp show [latest | RUN_ID | PERCORSO_FILE]
    (Alias: view)
    Visualizza con il paginatore di sistema il referto SOTU Master (SOTU_MASTER_REPORT.md).

  cdp list [runs | tests]
    runs: Elenca le sessioni storiche salvate in runs/.
    tests: Elenca il catalogo dei test della suite.

  cdp telemetry [ENDPOINT_URL | --endpoint <URL>] [--out <FILE>] [--samples <N>] [--quiet]
    Esegue la sonda ambientale sull'host (hardware, kernel, locale, versioni runtime) e misura la mediana RTT empirica.

  cdp stats <SOTTOCOMANDO> [OPZIONI]
    Invocatore del motore statistico (cdp_stats.py):
      binomial -k <K> -n <N> [--alpha <FLOAT>] [--out <FILE>]
        Calcola intervallo esatto Clopper-Pearson 95% su distribuzione Beta.
      paired-ttft --pairs-json <FILE> [--mde <MS>] [--alpha <FLOAT>] [--bootstrap-reps <N>] [--out <FILE>]
        Analisi differenze appaiate TTFT (Student-t, Bootstrap, MDE per T12).
      power --mde <DELTA_MIN> --pilot-sd <SD> [--power <FLOAT>] [--out <FILE>]
        Power Analysis a priori per dimensionamento campione N in regime R2.

  cdp unicode "<STRINGA>" [OPZIONI]
    Invocatore del motore Unicode UAX #15 (uax_engine.py):
      cdp unicode "<STRINGA>"
        Decomposizione scalari, codepoint e forme normalizzate (NFC, NFD, NFKC, NFKD).
      cdp unicode --file <PATH>
        Analisi Unicode da file di testo.
      cdp unicode --compare <S1> <S2> [--form <FORMA>]
        Valutazione equivalenza M2a tra due stringhe.
      cdp unicode --telemetry
        Telemetria tabelle Unicode e versione Python.

  cdp status
    Verifica integrita dei file, presenza del wrapper SUT (bash4llm), conteggio sessioni e hardening permessi (0700).

  cdp clean [tmp | all]
    tmp: Elimina le sandbox temporanee residue.
    all: Elimina l'intero archivio delle sessioni in runs/ (richiede conferma).

  cdp -?, -h, --help, help
    Visualizza questo manuale di riferimento.

4. GUIDA EPISTEMICA E REGOLE FORMALI (CDP/SOP v2.3)
========================================

1. PRINCIPIO AUREO DI CONSERVATIVITÀ EPISTEMICA:
   "Strength(Claim_reported) <= Strength(Evidence_observed)"
   Non e' mai consentito trarre conclusioni o attribuire certezze superiori a quanto effettivamente intercettato e registrato dagli strumenti sul confine misurato.

2. PROXY != MECCANISMO:
   La rilevazione di un effetto empirico (es. identita di testo, alterazione di stringa o variazione di latenza) dimostra COSA e' accaduto sui confini osservati, ma NON identifica automaticamente QUALE componente interno (pesi, tokenizzatore BPE, system prompt o routing distribuito) lo abbia generato.
   I layer interni inaccessibili (S, M_raw) rimangono formalmente UNDERDETERMINED.

3. POSTULATO DI NON-DIMOSTRAZIONE (NOT DETECTED != ABSENT):
   "not(Obs(X)) /=> not(X)"
   La mancata presenza di un carattere nell'output finale O attesta che esso non e' stato emesso in O, ma NON dimostra che non sia stato ricevuto o processato nei layer interni intermedi.

4. LA TRIADE DEI CLAIM E IL DIVIETO DI SALTO INFERENZIALE:
   Claim A (Osservazione) /=> Claim B (Localizzazione) /=> Claim C (Meccanismo)
   - Claim A: "Rilevata stringa X su C_req_unicode" (Puro dato empirico).
   - Claim B: "La mutazione e' avvenuta nel client prima della rete" (Richiede V3-3).
   - Claim C: "Il modello ha applicato una specifica regola BPE" (Vietato senza Layer V5).

5. MODALITÀ A (V3 ATTIVO) VS MODALITÀ B (BLACK-BOX PURA):
   - Modalita A (Layer V3-3 Verificato): Cattura del payload di richiesta (C_req) e risposta (C_resp). Consente di discriminare mutazioni Client-Side (H1a) da trasformazioni Post-Client (H2..H5).
   - Modalita B (V3-0a No-Capture): Osserva solo U -> O. Consente esclusivamente claim comportamentali terminali (Vettore E = < O1, C0, R1, S1 >).

6. REGIMI STATISTICI E POTENZA DEL CAMPIONE:
   - Regime Pilota R1 (N = 5): Screening esplorativo rapido. Con k=5 successi, il 95% CI esatto e' [0.4782, 1.0000] (non esclude tasso di errore reale fino al 52.2%).
   - Regime Vincolato R2 (N >= 20..50): Campione dimensionato via Power Analysis per escludere falsi positivi con Margine di Errore MOE <= 0.05.

7. THE QUADRUPLET RULE (I 4 PILASTRI DI OGNI REFERTO SOTU v2.3):
   Ogni referto generato contiene categoricamente:
   - OSSERVAZIONE: Fatti e byte misurati (digest SHA-256 su confini U/C/O).
   - INFERENZA: Spazio delle ipotesi logiche aperte sotto criterio M.
   - CONCLUSIONE: Ipotesi escluse o supportate sotto il Vettore E.
   - NON DETERMINATO: Esplicitazione rigorosa dei layer e fenomeni non osservati.
